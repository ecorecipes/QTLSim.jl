API reference

QTLSim.QTLSim — Module
QTLSim

A Julia port of QTSim, the quantitative-genetics simulation of Pagel, Gardner and Meade (Scientific Reports, 2025; the C source calls itself QTLSim 1.0): an additive polygenic trait under Gaussian stabilising viability selection toward an optimum that can move, with random mating, Poisson recombination and Poisson–Gaussian mutation. The kernel reproduces QTSim's numerics; validate/ compares it with QTSim and with the paper's published results.

The categorical layer, in which the population is an ACSet and the life cycle is a composite of operators (⋅) that can be stratified into demes (⊗), is the package extension QTLSimCatlabExt. Julia loads it when Catlab is loaded (import Catlab). Its functions are declared, documented and exported here.

Simulation

QTLSim.Params — Type
Params

Configuration for one simulation, with QTSim's defaults. Heritability is the narrow-sense heritability h² (a single scalar); MutationScalar is the mutation scalar m. The documentation's Parameters page lists every field with its meaning and its QTSim option. Values are checked when a World is made (see checkparams).

Some fields have no QTSim counterpart, or behave differently:

  • CrossoverModel: QTSim draws Poisson(RecombPoissonMean) crossover points per gamete but only the lowest one switches strands (its point index never advances), so a gamete has at most one crossover. :qtsim (default) reproduces that, as the published simulations did; :all applies every drawn point (the evidently intended Poisson-crossover model). With NoQTL == 1 the two are identical.
  • Drift: QTSim has the option but switches it off at the start of every run, so it never has an effect there. Here Drift = true makes every fitness 1: a neutral run, for comparison.
  • Demography and GrowthRate: QTSim always refills the population to PopSize, so it dies only when fewer than two survive one generation (:fixed, the default). With :beverton_holt the population is density-regulated, with carrying capacity PopSize and GrowthRate offspring per survivor at low density (see noffspring), so that it shrinks when mean fitness is low and can be rescued by adaptation.
  • MoveType = :red_noise or :periodic, with MoveNoiseSD, MoveAutocorr, MoveAmplitude and MovePeriod: QTSim's optimum moves by a rule; these two make it fluctuate, around a linear trend of MoveFitnessSD per generation, with stationary AR(1) noise or a sine wave (see moveoptimum!).

QTLSim.checkparams — Function
checkparams(p)

Throw an ArgumentError if p is not a model QTSim would run, or would run differently: Ploidy 1 or 2, at least one individual (two if diploid), locus, sampled generation and mutation per gamete; 0 ≤ Heritability ≤ 1 and PhenotypeVar > 0; MoveType one of :phenotype, :fitness, :continuous, :red_noise, :periodic (QTSim falls back to the phenotype move on an unknown name; a misspelt symbol here would silently change the model); MoveNoiseSD ≥ 0, 0 ≤ MoveAutocorr < 1, a finite MoveAmplitude and MovePeriod > 0; CrossoverModel :qtsim or :all; the schedules MoveFitnessSDGen and ChangeFitnessGen either −1 (off) or a generation, with ChangeFitnessSD > 0 when the width changes; and InitFitnessSD either −1 (the analytical width, which needs V_E > 0 and m > 0) or positive. Called by World(p).

source
QTLSim.World — Type
World

Mutable population state carried through the operators. Holds the current parents' genomes/environments, per-individual scratch (genotype/phenotype/ fitness), the survivor index set, the current selection optimum θ and width ω, and a double buffer (sgenome/senv) for the offspring generation.

Genomes are stored as (NoQTL, Ploidy, PopSize); the genotype of individual i is the sum over all its loci and chromosomes (QTSim CaclGenotype). The current population is individuals 1:N, with N == PopSize always under QTSim's Demography = :fixed; under density regulation N varies, PopSize is the carrying capacity, and Noff is the number of offspring in the buffer. θ0 and ε hold the state of a fluctuating optimum (MoveType = :red_noise or :periodic, see moveoptimum!).

QTLSim.simulate — Function
simulate(p::Params; seed=p.Seed)

Run one simulation from Params with a MersenneTwister(seed), returning the recorded statistics (see run!) and the seed. Without a seed one is drawn at random, and the returned seed reproduces the run.

The same seed gives the same run with the same versions of Julia and Distributions.jl: the streams of rand(rng, 1:n) and of the Poisson sampler are not guaranteed across their releases.

QTLSim.run! — Function
run!(w, rng; record=true)

Iterate the generation operator for NoGenerations, replicating QTSim's RunSim order: develop → select → reproduce → (record) → fitness-width change → mutate → swap. Returns a NamedTuple of per-sampled-generation statistics (gen, pheno_mean, pheno_var, geno_var, nsurv, theta, omega) plus extinct/extinct_gen.

source
QTLSim.generation! — Function
generation!(w, rng; rec = nothing)

One generation of QTSim's life cycle, develop ⋅ select ⋅ reproduce ⋅ record ⋅ rescale ⋅ mutate ⋅ swap, advancing the offspring into the current buffer and w.gen by one; record appends to rec (see records) when one is given. A no-op past extinction. On a fresh World, call init_env! first: run! is init_env! followed by NoGenerations of these.

QTLSim.init_env! — Function
init_env!(w, rng)

Draw the founders' environmental deviations, N(0, V_E) each (QTSim CreatePop, via SetIndividualEnv). run! and run_composed do this first; a World made with World(p) starts with all deviations zero, so call it before driving a fresh World with generation! or the operators directly.

QTLSim.records — Function
records(; demes = nothing)

Empty columns for the statistics record! collects, as run! returns them; with demes, a vector of Worlds, also the deme of each row.

source
QTLSim.record! — Function
record!(rec, w)

Append the parent generation's statistics to the columns rec (see records) every Sample generations (QTSim Output); a no-op when rec is nothing. Variances are sample variances (n − 1), as GSL's. Besides QTSim's columns it records the mean fitness W̄ (one minus the load) and the selection differential, the survivors' mean phenotype minus the mean phenotype, and the population size N (PopSize, unless the population is density-regulated).

QTLSim.rescale! — Function
rescale!(w)

Change the fitness width to ChangeFitnessSD at the end of generation ChangeFitnessGen, so that it takes effect from the next generation (QTSim RunSim).

QTLSim.develop! — Function
develop!(w)

Genotype = Σ allele effects; phenotype = genotype + environment (QTSim CaclPopPhenotype). Deterministic given the environments drawn at birth.

source
QTLSim.select! — Function
select!(w, rng)

Move the optimum, assign each individual a stabilizing-selection fitness, and draw the survivor set (survive iff rand() < fitness). Mirrors QTSim Fitness

  • SetSurviving. Sets w.extinct if too few survive to reproduce.

Fitness is the normalized Gaussian pdf(Normal(0,ω), (z−θ)/sd) / (0.4/ω), replicating QTSim exactly (the 0.4 ≈ 1/√(2π) constant included); the idealized form exp(−(z−θ)²/2ω²) is what Lean StabilizingSelection.lean proves about.

source
QTLSim.moveoptimum! — Function
moveoptimum!(w, rng = nothing)

Move the optimum θ if the schedule says so (QTSim SetFitnessMean). From generation t0 = MoveFitnessSDGen on, with d = MoveFitnessSD, z̄ the mean phenotype and t the generation:

  • :phenotype: θ = z̄ + √V_P·d;
  • :fitness: θ = z̄ + ω·d;
  • :continuous: θ += d;
  • :red_noise (Julia-only): θ_t = θ0 + d (t − t0) + ε_t, where θ0 is the optimum before the move and ε is a stationary AR(1) process with standard deviation σ = MoveNoiseSD and autocorrelation ρ = MoveAutocorr: ε_{t0} ~ N(0, σ²) and ε_t = ρ ε_{t−1} + σ √(1 − ρ²) ξ_t with ξ_t ~ N(0, 1). One normal draw per generation, from rng;
  • :periodic (Julia-only): θ_t = θ0 + d (t − t0) + A sin(2π (t − t0)/P), with A = MoveAmplitude and P = MovePeriod. Draws nothing.

The two fluctuating moves are exogenous: θ does not depend on the population. Their trend is d per generation, starting from θ0 at t0 (so a step behind :continuous, which already adds d at t0). With ρ = 0 the noise is white; as ρ → 1 it wanders more slowly with the same variance, so σ and ρ set the size and the time scale (−1/ln ρ generations) of the fluctuations separately.

source
QTLSim.fluctuating_optimum — Function
fluctuating_optimum(p, θ0, t, ε = 0.0)

The optimum of a fluctuating move t generations after it starts, from θ0: θ0 + d t + ε for MoveType = :red_noise, with the current noise ε, and θ0 + d t + A sin(2π t/P) for :periodic (see moveoptimum!). With ε = 0 it is the expected optimum under red noise.

source
QTLSim.reproduce! — Function
reproduce!(w, rng)

Fill the offspring buffer sgenome/senv by fitness-independent random mating among survivors (QTSim NewIn). Haploid: clone a random survivor. Diploid: two distinct survivors each contribute a (recombined) gamete. Offspring get a fresh environment. How many offspring is noffspring's: PopSize, as in QTSim, or under density regulation a number that depends on the survivors.

source
QTLSim.noffspring — Function
noffspring(w, rng)

The number of offspring the survivors produce. Under QTSim's Demography = :fixed it is PopSize, whatever the number of survivors, and draws nothing. Under :beverton_holt, with n survivors, carrying capacity K = PopSize and R = GrowthRate offspring per survivor at low density, it is Poisson(R n / (1 + (R − 1) n / K)), at most K: the population stays near K while survivors are plentiful, and declines when R·W̄ < 1.

source
QTLSim.mutate! — Function
mutate!(w, rng)

Add Gaussian mutations to the offspring buffer (QTSim MutateIndividualChrNo). Each chromosome receives Poisson(L·rate) mutations, each of variance m/(ploidy·L·rate)·V_E; in expectation this injects m·V_E of variance per individual per generation (Lean mutationalVarianceInput_eq).

source
QTLSim.gamete! — Function
gamete!(dest, chrA, chrB, rng, recombMean, L, allpoints=false, pts=Int[])

Build one gamete from a parent's two chromosomes (QTSim CreateCombMap + RecombinationPoissonChr). Draw Poisson(recombMean) distinct crossover points in 0:L-2 (none if the count is 0 or ≥ L), start on a random parental chromosome, and switch strands after crossover points. QTSim never advances its point index, so only the LOWEST point switches: a gamete has at most one crossover. That is the default; allpoints=true switches at every point (Params CrossoverModel = :all). With L == 1 both reduce to picking one parental chromosome at random (Mendelian segregation).

source
QTLSim.swapbuffers! — Function

Swap the parent and offspring buffers (QTSim double-buffer swap).

Sweeps and replicates

QTLSim.sweep — Function
sweep(f, jobs; cache = nothing, id = identity, cost = nothing,
      ntasks = Threads.nthreads(), progress = 0)

Apply f to every job in jobs and return the results in the order of jobs.

Jobs are handed out one at a time to ntasks tasks on Julia's threads, so a long job never holds up a queue of others (the greedy scheduling of Threads.@threads :greedy, which needs Julia 1.11; :dynamic gives each thread a fixed block of jobs). With cost, a function of a job, the costliest jobs start first, which shortens a sweep whose jobs differ in cost. Neither changes the results, provided f takes its randomness from the job (a seed) rather than from a shared generator: the results then do not depend on the number of threads or on the order in which the jobs run.

With cache, the path of a CSV file, f must return a NamedTuple of numbers, Bools, strings or symbols, with the same fields for every job. Each row is appended to the file as soon as it is computed, after a first column id holding string(id(job)), and jobs whose id is already in the file are not run again, so an interrupted sweep resumes where it stopped. The rows returned are those of the file, for jobs run now as for jobs run before, so a resumed sweep returns the same rows as an uninterrupted one. Each column comes back as the narrowest of Bool, Int, Float64 and String that reads all its values (Float64s round-trip exactly; symbols, and strings that read as numbers, do not). A line cut short by an interruption is dropped. Two jobs with the same id, and a file whose columns differ from the rows, are errors; rows of ids not among jobs are kept in the file and ignored.

If f throws, no further jobs start, the jobs already running finish (and are cached), and the first error is logged with its job and rethrown.

progress = k prints a line every k finished jobs.

# 20 runs of each of three mutation scalars, cached, resumable
jobs = [(; m, seed) for m in (0.001, 0.005, 0.02) for seed in 1:20]
rows = sweep(jobs; cache = "runs.csv", id = j -> "$(j.m)-$(j.seed)") do j
    o = simulate(Params(MutationScalar = j.m, NoGenerations = 2000); seed = j.seed)
    (; j.m, j.seed, VG = o.geno_var[end])
end

QTLSim.replicate — Function
replicate(p::Params, n; seed = 1, summary = identity, kw...)

Run n simulations of p with the seeds seed, seed + 1, …, seed + n - 1, in parallel, and return summary of each run's output (see simulate), in the order of the seeds. The runs go through sweep, which takes the other keywords. A cache is keyed by the seed, and summary must then return a NamedTuple.

VG = replicate(Params(NoGenerations = 2000), 100; summary = o -> o.geno_var[end])

QTSim options files

QTLSim.read_qtsim_options — Function
read_qtsim_options(path_or_io) -> Params

Read a QTSim options file into Params, as QTSim's PassOptFile reads it:

  • one Keyword value… per line, keywords case-insensitive;
  • a line whose first word starts with # is a comment;
  • MoveFitnessSD <generation> <size> and ChangeFitnessSD <generation> <width> take two values;
  • StandardisePhenotype and Drift take none and switch their option each time they appear.

The seed (Seed) goes into Params' Seed field. Note that QTLSim's random numbers are not QTSim's, so the same seed reproduces a QTLSim run, not the QTSim run.

Where the files differ from Params' field names:

QTSim keywordParams field
GenerationsNoGenerations
MoveFitnessSD g dMoveFitnessSDGen = g, MoveFitnessSD = d
ChangeFitnessSD g wChangeFitnessGen = g, ChangeFitnessSD = w
OptimumMoveTypeMoveType (:phenotype, :fitness, :continuous)
RecombinationPoissonMeanRecombPoissonMean

The other keywords (Sample, PopSize, NoQTL, Ploidy, PhenotypeVar, Heritability, MutationScalar, MutationRatePerGamete, InitFitnessSD, StandardisePhenotype) are field names.

Two rules differ from QTSim's:

  • An unknown keyword is an ArgumentError, as it is an error in QTSim. So is an unknown move type, which QTSim silently ignores, keeping the phenotype move.
  • Drift is read but dropped with a warning: QTSim switches drift off at the start of every run, so the option never has an effect there.

See also write_qtsim_options.

source
QTLSim.write_qtsim_options — Function
write_qtsim_options(path_or_io, p::Params; seed = p.Seed)

Write p as a QTSim options file, the inverse of read_qtsim_options: every option QTSim reads, with QTSim's keywords. The seed is written when there is one. QTSim cannot express two Params settings, so the file warns for them:

  • CrossoverModel = :all: QTSim applies only the lowest crossover point;
  • Drift = true: QTSim switches drift off.

It is an ArgumentError to write MoveType = :red_noise or :periodic: QTSim has no fluctuating optimum, and would run a different model.

Theory

The predictions the simulations are compared with; run_moments iterates them for any life cycle.

QTLSim.selection_variance — Function
selection_variance(p) -> V_s

The width of stabilising selection on the genotype, V_s = ω² + V_E, for the initial fitness width ω of p (initFitSD). Selection on a phenotype z = G + E with E ~ N(0, V_E) acts on G as Gaussian selection of variance ω² + V_E.

source
QTLSim.gaussian_vg — Function
gaussian_vg(p)

The Gaussian approximation to the equilibrium genetic variance under mutation–selection balance, √(V_m V_s), with V_m = m·V_E (muteVar) and V_s from selection_variance (Lande 1975). It ignores drift, and does not depend on the number of loci. The moments lowering (run_moments) has the slightly larger fixed point gaussian_vg_exact.

source
QTLSim.gaussian_vg_exact — Function
gaussian_vg_exact(p)

The fixed point of the Gaussian recursion V ← V − V²/(V_s + V) + V_m, which the moments lowering iterates: (V_m + √(V_m² + 4 V_m V_s))/2. It is √(V_m V_s)·(1 + O(√(V_m/V_s))), close to gaussian_vg when mutation is weak relative to selection (Lean gaussian_fixed_point).

source
QTLSim.effective_size — Function
effective_size(N, nsurv)

Falconer's effective size N_e = 4N/(V_k + 2) when nsurv of the N individuals survive and each of the next generation's 2N gametes comes from a survivor chosen at random: the number a survivor contributes is binomial, with variance V_k = 2N (nsurv − 1)/nsurv². With every individual surviving, N_e ≈ N.

source
QTLSim.house_of_cards_vg — Function
house_of_cards_vg(p; nsurv = p.PopSize)

Bürger's stochastic house-of-cards approximation to the equilibrium genetic variance, 4nμ V_s / (1 + V_s/(N_e α²)), with n loci, mutation rate μ per locus per gamete, α² = V_m/(2nμ) the variance of one mutation's effect, and N_e from effective_size with nsurv survivors per generation (Bürger 1989; the paper's Supplementary Figure S1). Unlike gaussian_vg, it grows with the number of loci.

source
QTLSim.steady_lag — Function
steady_lag(k; VG, Vs)
steady_lag(p; VG)

The lag θ − z̄ at which a population whose mean responds to Gaussian selection keeps pace with an optimum moving k per generation: k (V_G + V_s)/V_G (Lande; Bürger and Lynch 1995). The response to a lag λ is V_G λ/(V_G + V_s) per generation, which equals k at that lag (Lean steady_lag_response). With p, k = MoveFitnessSD and V_s = selection_variance(p), for MoveType = :continuous.

source
QTLSim.critical_rate — Function
critical_rate(; n, VG, ω, VE, sd50, N)

Bürger and Lynch's critical rate of environmental change, as the paper's results table computes it, in units of the phenotypic standard deviation sd50 at 50% mortality:

k_c = V_G/(V_G + V_s) · √(2 V_λ ln B₀),   V_s = ω² + V_E,  V_λ = V_s + V_G + V_s/(2N_e),
B₀ = N₀ ω/√V_λ,   N₀ = N(2n − 3)/(2n(n − 2)),   V_k = 2N₀(1 − 2N₀/N),  N_e = 4N/(V_k + 2),

where n is the number of survivors at the table's generation 10,047 and V_G the genetic variance just before the move. NaN where the table has none: n < 3, or B₀ ≤ 1. (The paper's equation 2 is printed without the factor 2 and with V_s + V_G for V_λ; this form reproduces its table to machine precision, see vignette 09.)

QTLSim.mutation_adjusted — Function
mutation_adjusted(rate, m, dist; w = ones(length(m)))

The paper's equation 1: each rate in rate weighted by the density of its population's mutation scalar m under dist (the paper's gamma distribution: the maximum-likelihood fit to all 119,984 mutation scalars, shape 1.201 and scale 0.004635), relative to the (w-weighted) mean density.

QTLSim.extinction_distribution — Function
extinction_distribution(p, Wbar; N0 = p.PopSize, from = 0, method = :chain)
extinction_distribution(p, m; from = 0, method = :chain)

The distribution of the time to extinction from demographic stochasticity alone, along a deterministic trajectory of mean fitness: Wbar[t+1] is the mean fitness W̄_t in generation t, or m is the result of run_moments(p) (with Sample = 1), whose mean_fitness it takes. The population starts with N0 adults in generation 0; with from, the stochastic process starts in generation from, with the deterministic size of that generation, and is certain to survive before it.

In generation t each of the N_t adults survives with probability W̄_t (viability selection; the binomial ignores the variation of fitness among individuals), and the population is lost if fewer than two survive (one, if haploid). Under QTSim's Demography = :fixed the survivors are replaced by PopSize offspring, so each generation is an independent trial, lost with probability P(Binomial(PopSize, W̄_t) < 2). Under :beverton_holt the n survivors have min(K, Poisson(R n/(1 + (R − 1) n/K))) offspring (noffspring), and method chooses how this is followed:

  • :branching: the density dependence is linearised along the deterministic trajectory. Each survivor has Poisson(r_t) offspring independently, with r_t = R/(1 + (R − 1) n_t/K) the per-capita rate at the expected number of survivors n_t = N_t W̄_t, so the adults form a Galton–Watson process in a varying environment, with per-adult generating function φ_t(s) = 1 − W̄_t + W̄_t exp(r_t (s − 1)) (survival thins the Poisson). Then P(extinct by T) = (φ_from ∘ ⋯ ∘ φ_T)(0)^{N_from}, by backward iteration. This ignores the cap and the need for two parents, and, near K, the regulation that pulls the size back to the trajectory, so it overstates the spread of sizes and brings extinction forward (vignette 10);
  • :chain (the default): the exact distribution of the size given the trajectory, a Markov chain on 0:K driven by W̄_t, with the binomial survival, the cap at K and the need for two parents. It takes about a second for K = 1000 and 2000 generations.

Returns (; gen, pext, median, psurvive): the generations from:T−1, P(extinct by the end of generation t) for each, the median generation of extinction (missing if pext stays below one half), and the probability of surviving the whole trajectory. A trajectory m that run_moments ends with a deterministic extinction in generation m.extinct_gen is certain to be extinct by then (the last gen, with pext = 1).

source
QTLSim.rescue_probability — Function
rescue_probability(; N0, R, d0, VG, VE, ω, Wmax = 1, T = 10_000)

Gomulkiewicz and Holt's (1995) evolutionary rescue after an abrupt shift of the optimum by d0, on QTLSim's life cycle without density regulation. Fitness is Wmax·exp(−(z − θ)²/(2ω²)), so with phenotypic variance V_P = V_G + V_E and lag d_t the mean fitness is W̄_t = Wmax·ω/√s · exp(−d_t²/(2s)), s = ω² + V_P, and the lag shrinks as d_{t+1} = (1 − V_G/s) d_t (V_G constant). Each adult survives with probability W̄_t and has Poisson(R) offspring, so the population is a Galton–Watson process with generating function 1 − W̄_t + W̄_t exp(R(u − 1)), and the probability that N0 adults leave descendants for ever is one minus its extinction probability, computed by backward iteration from the fixed point of the limiting generation (after T generations). (Wmax = 1/(0.4√(2π)) ≈ 0.997 is the peak of QTSim's fitness.)

Returns (; rescue, Nmin, tmin): the probability of rescue, and the minimum of the deterministic size N_{t+1} = R W̄_t N_t and the generation it is reached (Gomulkiewicz and Holt's criterion compares Nmin with a critical size). rescue = 0 when the limiting growth R W̄_∞ ≤ 1.

Fluctuating optima (MoveType = :periodic or :red_noise):

QTLSim.periodic_response — Function
periodic_response(P; VG, Vs)

The steady response of the mean phenotype to an optimum that cycles with period P generations, θ_t = A sin(2π t/P), when the mean follows z̄_{t+1} = z̄_t + β (θ_t − z̄_t) with β = V_G/(V_G + V_s). With ν = 2π/P, the mean cycles as z̄_t = gain·A sin(ν t − phase), where

D = √(1 − 2(1 − β) cos ν + (1 − β)²),   gain = β/D,
phase = atan(sin ν, cos ν − (1 − β)),

and delay = phase/ν is the phase lag in generations. The lag θ − z̄ cycles with amplitude lag_amplitude·A, lag_amplitude = 2 sin(ν/2)/D. A slow cycle (P → ∞) is tracked with gain → 1 and delay → 1/β, the delay of the steady lag behind a trend; a fast one is averaged out (gain → 0). Returns (; gain, phase, delay, lag_amplitude).

source
QTLSim.red_noise_lag_var — Function
red_noise_lag_var(σ, ρ; VG, Vs)

The stationary variance of the lag θ − z̄ when the optimum is AR(1) noise with standard deviation σ and autocorrelation ρ, θ_t = ρ θ_{t−1} + σ√(1 − ρ²) ξ_t, and the mean follows z̄_{t+1} = z̄_t + β (θ_t − z̄_t) with β = V_G/(V_G + V_s):

E[(θ − z̄)²] = 2σ² (1 − ρ) / ((2 − β)(1 − ρ (1 − β))).

White noise (ρ = 0) gives 2σ²/(2 − β), more than σ², as the mean chases noise that has already gone; slowly wandering noise (ρ → 1) is tracked and the lag vanishes.

source
QTLSim.expected_lag2 — Function
expected_lag2(p; VG)

The expected squared lag E[(θ − z̄)²] of a population with genetic variance VG under the move of p, once the response is steady, with V_s = selection_variance(p): the squared steady_lag of the trend d = MoveFitnessSD, plus, for MoveType = :red_noise, red_noise_lag_var, or, for :periodic, the cycle's mean squared lag (lag_amplitude·A)²/2 (periodic_response). For :continuous it is the squared steady lag. The trend and the fluctuation add because the response is linear and the fluctuation has mean zero (over a cycle, for :periodic).

source
QTLSim.lag_load — Function
lag_load(p; VG)

The expected lag load on the log scale: the mean of ln W̄(0) − ln W̄(λ) for a lag λ, E[λ²]/(2(ω² + V_P)) with V_P = VG + V_E, ω the initial width and E[λ²] from expected_lag2. Gaussian selection of width ω on z ~ N(z̄, V_P) gives ln W̄(λ) = ln W̄(0) − λ²/(2(ω² + V_P)) (Lande and Shannon 1996).

The categorical layer

These functions are implemented by the package extension QTLSimCatlabExt, which Julia loads when Catlab is loaded:

using QTLSim

The life cycle and its lowerings

QTLSim.lifecycle — Function
lifecycle()

The life cycle as syntax: a named tuple of the Catlab presentation (presentation) of the free symmetric monoidal category whose objects are the stages of a generation (Zygotes, Adults, Survivors, Offspring), its generating steps (develop, select, reproduce, record, rescale, mutate, swap), QTSim's generation (generation), their composite develop ⋅ select ⋅ reproduce ⋅ record ⋅ rescale ⋅ mutate ⋅ swap, a morphism Zygotes → Zygotes, and migrate, where migrate(k) is the step that exchanges offspring among k demes, Zygotes^⊗k → Zygotes^⊗k, and migrate(k; rate) the same step at its own rate, a number or a migration matrix. Composites type-check: a step can follow another only where the stages match. Catlab's ⊗ places life cycles side by side, one per deme: generation ⊗ generation ⋅ migrate(2) is a generation of two demes coupled by migration. withparams gives steps parameters of their own, and lower gives a life cycle its meaning in a backend. Requires Catlab.

QTLSim.withparams — Function
withparams(f; kw...)

The life-cycle morphism f with parameters given to its steps. Each generator of f that takes one of the parameters in kw becomes a new generator of the same type, named by the step and its parameters. Its image in each lowering (:kernel, :eidos, :moments) is the image of the plain step with those parameters in place of the deme's Params, for that step only. The parameters each step takes:

  • select: ω, a fixed width; θ, a fixed optimum, in place of the move; the move, MoveType, MoveFitnessSD, MoveFitnessSDGen, MoveNoiseSD, MoveAutocorr, MoveAmplitude and MovePeriod; StandardisePhenotype and Drift;
  • reproduce: RecombPoissonMean, CrossoverModel (:qtsim only in Eidos), Demography and GrowthRate;
  • record: Sample;
  • rescale: ChangeFitnessGen and ChangeFitnessSD;
  • mutate: MutationScalar and MutationRatePerGamete;
  • migrate: rate, a number or a migration matrix, in place of the lowering's migration_rate. lifecycle().migrate(k; rate) is the same.

So withparams(L.select; ω = 0.3) is a selection step of width 0.3, and withparams(g; θ = 0.1) ⊗ g a generation of two demes whose first selects toward 0.1. L.develop ⋅ withparams(L.select; ω = 0.3) ⋅ withparams(L.select; ω = 1.0) ⋅ … is a life cycle with two selection steps of different widths. A parameter that no step of f takes is an ArgumentError, as is a value that Params would reject. Giving parameters to a step that already has some merges them, the new ones winning. Two generators are equal when their steps and parameters are.

A step's parameters leave the deme's state alone. Its optimum θ and width ω are restored after a step with its own, so the theta and omega columns of the records are the deme's; but a move made with a step's own move parameters moves the deme's optimum, as a move does. In Eidos the overridden constants become literals in that step's code. Steps without parameters lower exactly as before. Requires Catlab.

QTLSim.lower — Function
lower(f, target; images = Dict(), record = nothing, migration_rate = 0.0)

The image of the life-cycle morphism f under the lowering functor to target: :kernel gives an operator on a World, :eidos a fragment of Eidos code for SLiM, in which @POP@ stands for the deme's subpopulation, and :moments an update of the moments of a Gaussian population, the predictions of theory (see run_moments). A morphism between products of stages, one per deme, has an image on several demes: an operator on demes of a metapopulation (DemeOp, in the kernel and the moments lowering), or Eidos for several subpopulations (EidosMeta). A functor out of a free category is fixed by the images of the generators, so the image of a composite or a product is the composite or product of the images. record steps in the kernel append the parent generation's statistics to record, a named tuple of vectors like the one run! returns, or discard them when it is nothing; migrate steps exchange individuals among demes at migration_rate (in Eidos, the constant migRate), or along a migration graph when it is a matrix (island_migration, stepping_stone; in Eidos, the constant MIG), unless the step has a rate of its own (lifecycle().migrate(k; rate)).

A step with parameters (withparams) is a generator of its own. Its image is the plain step's, with the step's parameters in place of the deme's Params; in Eidos they are literals in the step's code. Steps that are not in lifecycle, made with Catlab's Hom(name, dom, codom), need an image in images, keyed by name: an operator or a function (state, rng) -> state for :kernel and :moments, a string of Eidos for :eidos. A key that is the name of a step with parameters, first(Catlab.args(s)) for the generator s, gives that step its own image. Eidos steps keep a deme's state on its subpopulation: @POP@.getValue("THETA") and @POP@.getValue("OMEGA") are its optimum and fitness width, set with setValue, and the steps before select leave adults, genotype and pheno defined. Requires Catlab.

QTLSim.slim_script — Function
slim_script(f, p::Params; images = Dict(), migration_rate = 0.0)
slim_script(f, ps::Vector{Params}; images = Dict(), migration_rate = 0.0)

A complete SLiM model, as Eidos source, that iterates the life cycle f, a morphism Zygotes → Zygotes, or Zygotes^⊗k → Zygotes^⊗k for k demes, each a subpopulation of p.PopSize individuals: the image of f under lower to Eidos runs once per tick in a reproduction() callback, so f is one generation of each deme. The parameters of p and migration_rate are the defaults, which slim -d "NAME=value" overrides (N, VP, h2, m, rate, L, RECOMB, NGEN, sampleEvery, moveGen, moveSD, moveType, changeGen, changeSD, initOmega, drift, standardise, demography, growthRate, migRate or MIG, and with a fluctuating move moveNoiseSD, moveAutocorr, moveAmplitude and movePeriod). The Eidos images of the steps cover diploids (Ploidy = 2) with any number of loci, recombining as QTSim does (CrossoverModel = :qtsim); with several demes, each row of output ends with the deme. The life cycle must return each deme to its place: braidings must cancel.

With ps, one Params per deme, the demes have parameters of their own, as ps ⊗ demes(k) gives them in the kernel. A constant whose value differs between demes is a vector, one value per deme, which each deme keeps on its subpopulation, and the deme's code reads @POP@.getValue("NAME"); so do the derived constants (VE, ESD, MUTVAR). Every field of the list above can differ, except NoQTL, NoGenerations, Ploidy, CrossoverModel and Demography, which must be the same in every deme. With equal ps the model is the one of a single Params. Steps with parameters (withparams) override the deme's values in their own code. Requires Catlab.

QTLSim.run_composed — Function
run_composed(w::World, rng; record = true, cycle = lifecycle().generation, images = Dict())
run_composed(s, rng; cycle, record = true, images = Dict(), migration_rate = 0.0)

Run a simulation by applying the kernel image of the life cycle cycle, a morphism Zygotes → Zygotes, once per generation (lower; images gives the kernel images of steps that are not in lifecycle). Returns the statistics its record steps collect, as run! does; with the default life cycle, for the same seed, it is the same run as run!, bit for bit. For a metapopulation s = p ⊗ demes(k), cycle is a life cycle on k demes, such as g ⊗ g ⊗ g ⋅ lifecycle().migrate(3) for k = 3, and the statistics have a row per deme and sampled generation (deme), with extinct_gen per deme. A life cycle of several generations, such as withparams(g; ω = 0.2) ⋅ withparams(g; ω = 1.0) (seasons of different selection), runs whole cycles until NoGenerations generations are done; each swap advances the generation. Requires Catlab.

QTLSim.run_moments — Function
run_moments(p::Params; cycle = lifecycle().generation, images = Dict(), zbar = 0.0, VG = 0.0,
            optimum = nothing, erosion = false, migration_rate = 0.0)
run_moments(ps::Vector{Params}; cycle, images = Dict(), zbar = 0.0, VG = 0.0, erosion = false,
            migration_rate = 0.0)

The life cycle cycle lowered to the moments of a Gaussian population (lower(cycle, :moments)) and iterated for NoGenerations: the deterministic, infinite-population predictions of quantitative-genetic theory for the same morphism the kernel and SLiM simulate. Each step's image updates the means and variances:

  • develop: V_P = V_G + V_E;
  • select: moves the optimum as MoveType says, then applies Gaussian selection of width ω to z ~ N(z̄, V_P). This gives the mean fitness, the expected survivors N·W̄, the selection differential, and the survivors' genotypic mean and variance z̄ + V_G λ/s and V_G − V_G²/s, with λ = θ − z̄ and s = ω² + V_P;
  • reproduce: passes those to the offspring (the continuum-of-alleles approximation, no drift); with erosion = true, drift erodes the offspring's genetic variance by the factor 1 − 1/(2 N_e), with N_e the expected number of survivors, which mate at random;
  • mutate: adds m·V_E.

The expected population size is PopSize, or under Demography = :beverton_holt the mean of noffspring for the expected survivors, R n/(1 + (R − 1) n/K).

Returns the columns of run!, predicted (nsurv rounded). The genetic variance converges to gaussian_vg_exact; under a continuous move the lag θ − z̄ converges to steady_lag. The population is extinct when fewer than two individuals (one, if haploid) are expected to survive; extinction_distribution adds the demographic stochasticity along the trajectory. Requires Catlab.

The fluctuating moves lower to their expected optimum (fluctuating_optimum without noise): MoveType = :periodic exactly, since it is deterministic, and :red_noise as its linear trend. To follow one realisation of the noise, pass the optimum of every generation as optimum (optimum[t + 1] for generation t, at least NoGenerations values; for example theta from a kernel run with Sample = 1). It replaces the move whatever MoveType is, and the prediction is then the Gaussian population's response to that environment (expected_lag2 gives its average). One deme only.

Several demes. For a life cycle on k demes, such as g ⊗ g ⋅ lifecycle().migrate(2), p is every deme's Params; ps, a vector, gives each deme its own, and zbar and VG may be vectors, one value per deme. The statistics have a row per deme and generation (deme), and extinct_gen is per deme, as from run_composed. The image of migrate is the kernel's migration (migrate!) at the level of first and second moments. With M[a, b] the probability that a visit to an individual of deme a starts an exchange with deme b (rate/(k − 1) for a number) and N the deme sizes, the expected fraction P[a, c] of deme a that comes from deme c follows from visiting the demes in order: while deme a is visited, deme b moves toward a's composition by a factor f = (1 − M[a, b]/N_b)^{N_a}, and a receives N_b (1 − f) times the difference on top of what it sends. A deme then has mean Σ_c P[a, c] z̄_c and genetic variance Σ_c P[a, c] V_c + Σ_c P[a, c] (z̄_c − z̄_a)², within-deme plus between-deme variance, and migrants keep their environmental variance. The means are exact in expectation, and so are the variances right after migration, up to the sampling of the numbers of migrants. The lowering carries the between-deme part as genic variance afterwards, as it does the reduction by selection. In the simulations, part of it is association within individuals, which segregation and recombination break up (at one locus, half of it goes at the next reproduction), so the kernel's variance falls below the moments' after mixing.

QTLSim.operators — Function
operators()

The kernel images of the steps of the life cycle (lifecycle), as the named tuple (; develop, select, reproduce, record, rescale, mutate, swap, generation). An operator is called as op(world, rng), composes left to right with Catlab's ⋅ ((f ⋅ g)(w, rng) applies f then g), and acts deme by deme on a metapopulation built with ⊗. generation is the image of QTSim's generation, develop ⋅ select ⋅ reproduce ⋅ record ⋅ rescale ⋅ mutate ⋅ swap, in the order of its generation loop; here record discards what it observes (see run_composed). Requires Catlab.

QTLSim.operator — Function
operator(name::Symbol, act; scope = :deme)

A new operator that applies act(state, rng) and returns the state. With scope = :deme it acts on one population (a World) and is applied to each deme of a metapopulation; with scope = :meta it acts on the whole metapopulation, as migration does. Requires Catlab.

QTLSim.demes — Function
demes(k)

Stratification into k demes: p ⊗ demes(k) with p::Params gives k independent populations, [p1, …, pk] ⊗ demes(k) gives demes with their own parameters (for example the width of selection, or the size; the same NoGenerations), and w ⊗ demes(k) with w::World gives k copies of w. Requires Catlab.

source
QTLSim.migrate! — Function
migrate!(s, rng; rate = 0.01)

Move individuals between the demes of a metapopulation s: each individual starts a swap with probability rate, exchanging places with a random individual of a random other deme, so the deme sizes are unchanged. Returns (; count), the number of exchanges. Requires Catlab.

rate is not the island model's migration rate m: an individual also moves when another deme's swap picks it, so with equal deme sizes about 2·rate of each deme is replaced per generation (each exchange moves two individuals). Use m/2 for an island-model rate m. The SLiM lowering (migRate) does the same.

When rate is a matrix M (island_migration, stepping_stone), an individual of the deme in position a starts an exchange with probability M[a, b] with a random individual of the deme in position b: migration along a graph. One uniform draw decides whether and where, so a matrix draws differently from a number, even island_migration(k, r), which is the same model as rate = r. Demes must have the same loci and ploidy, and may differ in size.

QTLSim.island_migration — Function
island_migration(k, m)

The island model on k demes: an individual starts an exchange with probability m, with a deme chosen uniformly among the other k − 1. As a matrix, m/(k − 1) off the diagonal. Equivalent in distribution to migration_rate = m.

stepping_stone(k, m; circular = true)

The stepping-stone model on k demes in a line (or a ring, when circular): an individual starts an exchange with probability m, with one of its neighbours, each with probability m/2. At the ends of a line, the one neighbour gets m/2.

Types of the extension

QTLSimCatlabExt — Module
QTLSimCatlabExt

The categorical layer of QTLSim, loaded with Catlab. The life cycle is a morphism of a free category whose objects are the stages of a generation (lifecycle.jl), lowered by functors to the simulation kernel, where each step is an Operator composed with Catlab's ⋅ and stratified into demes with its monoidal product ⊗ (compose.jl), and to a SLiM model in Eidos (eidos.jl), and to the deterministic recursions of quantitative-genetic theory on a Gaussian population's moments (moments.jl). The population is an attributed C-set (ACSet) on the schema of schema.jl. The facts that justify the decomposition, that composition is associative, that a run is the iterate of one composed generation and that a lowering is fixed by its action on the steps, are proved in lean/CategoricalQuantGen/Composition.lean and Lowering.lean.

QTLSimCatlabExt.migration_mixing — Function
migration_mixing(M, N, alive)

The expected composition of the demes after the kernel's migration (migrate!), with M[a, b] the probability that a visit to an individual of deme a starts an exchange with a random individual of deme b, N the deme sizes and alive which demes take part: P[a, c] is the expected fraction of deme a that came from deme c.

migrate! visits the demes in order, and each individual of a deme once. When deme a is visited, its individuals all have the composition of the deme, P[a, :] (earlier demes chose partners in it at random), and its unvisited ones do not change while it is visited. Each visit exchanges with deme b with probability r = M[a, b], sending an individual of composition P[a, :] and receiving a random one of b, whose expected composition moves toward P[a, :] by a factor 1 − r/N_b per visit. Over the N_a visits, with f = (1 − r/N_b)^{N_a}, deme b becomes P[a, :] + f (P[b, :] − P[a, :]) and deme a receives N_a r P[a, :] + N_b (1 − f)(P[b, :] − P[a, :]), in place of the N_a r individuals it sends. These expectations are exact for any deme sizes.
