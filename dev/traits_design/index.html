Several traits: a second model through the same life cycle

QTLSim's categorical layer writes QTSim's life cycle once, as a morphism of a free symmetric monoidal category (lifecycle()), and lowers it by functors to the kernel, to SLiM and to the moments of a Gaussian population. The north star is a framework of which QTSim is one instance. This note records what happened when a second model went through the same syntax and lowerings: n quantitative traits with pleiotropy (Lande 1979, 1980; Jones, Arnold and Bürger 2003, 2007). It is a test of whether the decomposition generalises.

The model

  • NoTraits = n traits (any n ≥ 1; n = 1 is QTSim). Each locus carries a vector of n allelic effects, and the genotype g ∈ ℝⁿ is their sum.
  • The phenotype is z = g + e, with e ~ N(0, V_E I): every trait has QTSim's V_E = (1 − h²) V_P, independently.
  • A mutation adds a draw from N(0, M/(Ploidy·NoQTL·rate)) to a uniformly chosen locus, so that the expected input per individual per generation is the mutational covariance M: m·V_E on the diagonal and r_μ·m·V_E off it (MutCorr), or MutCov.
  • Fitness is QTSim's Gaussian in n dimensions, W(z) = c·exp(−½ (z−θ)ᵀ Ω⁻¹ (z−θ)), with QTSim's c = 1/(0.4√(2π)) ≈ 0.9974, so that n = 1 is QTSim's fitness exactly. Ω = ω² S: the scalar width ω (initial width, changed by rescale as in QTSim) times a shape S with unit diagonal and correlation r_ω (SelCorr), or SelCov/ω₀². Selection is viability (or fecundity) selection, as for one trait.
  • The optimum θ ∈ ℝⁿ moves along a unit direction u (MoveDirection, trait 1 by default): θ += d·u (:continuous), θ = z̄ + √V_P·d·u (:phenotype) or θ = z̄ + ω·d·u (:fitness). Selection on one trait then acts on the others through G's and Ω's correlations (Lande and Arnold 1983).

Findings: the syntax did not change

lifecycle() is unchanged. The stages (Zygotes, Adults, Survivors, Offspring) and the steps (develop, select, reproduce, record, rescale, mutate, swap) are the same generators, QTSim's generation is the same composite, migrate(k) and ⊗ are the same. No new generator was needed. Every lowering of the trait model is a functor out of the same free category; what differs is where it sends the generators:

one trait (QTSim)n traits
object image (an individual at a stage)g, e, z ∈ ℝg, e, z ∈ ℝⁿ
developz = Σ effects + ethe same, per trait
selectW = c·exp(−(z−θ)²/2ω²), θ moves by a ruleW = c·exp(−½ (z−θ)ᵀΩ⁻¹(z−θ)), θ moves along u
reproducegametes copy blocks of locithe same code: a block holds n values per locus
recordQTSim's columnsthe same, plus trait means, G, P, lag and selection differential vectors
rescaleω ← ChangeFitnessSDthe same: Ω = ω² S scales with it
mutate+N(0, σ²) at a random locus+N(0, M/(2L·rate)) at a random locus
swapswap buffersthe same, with the trait environments

reproduce, rescale and swap have literally the same images: recombination and inheritance do not care what an allele is, only that it can be copied. migrate's image is the same too (a migrant's genome is block ids; only its environment vector had to move with it). So the functor table changes only in develop, select, mutate and record, and only because the object image changed from ℝ to ℝⁿ.

The ACSet schema is unchanged too. SchPopulation (Individual, Allele, owner, attributes effect, env, genotype, phenotype, fitness) is the same presentation; a population of n traits is an ACSet on it with vector-valued attribute types, PopulationACSet{Vector{Float64},Vector{Float64}} (TraitPopulation). The genotype is still the sum over the preimage owner⁻¹(i), now in ℝⁿ. In categorical terms the model changed the attribute functor, not the schema.

In the language of the north star: the n-trait model is a family of functors F_n : LifeCycle → Kern, indexed by the object image ℝⁿ, with F_1 QTSim's. The lowerings are fixed by their images on the generators (Lowering.lean), so F_n's generation is the composite of its steps' images by the same theorem, with no new proof obligation about the wiring. The new obligations are about the images: that mutate injects M (the multivariate mutationalVarianceInput_eq) and the Gaussian recursion's fixed point (see "For Lean" below).

Where it did not work that way

These are the places where the generalisation was not free, as first found. Items 1–3 have since been addressed by making the model explicit (next section); the notes record the original finding.

  1. Step parameters belong to the model, not to the syntax. A generator carries parameters (withparams(select; ω = 0.3), the table STEP_PARAMS). The bare presentation is model-independent, but the parameter vocabulary of each step is not: the trait model's select reads SelCorr/SelCov/MoveDirection, its mutate reads MutCorr/MutCov, and a fixed optimum θ is a vector. The parametrised generators Step(name, params) range over a model-specific parameter space. At first steps with parameters took the scalar parameters only. Now addressed: each model types its steps' parameters (step_schema), a vector θ and a matrix Ω included.
  2. The optimum's move is not a function of the syntax. QTSim's moves are rules about a scalar; with several traits they need a direction, a new parameter of select's image. The fluctuating moves (:red_noise, :periodic) are not generalised (a direction for the trend and a covariance for the noise would be needed) and checkparams rejects them with NoTraits > 1, as it does StandardisePhenotype. Now addressed: the fluctuating moves have a trend along u and fluctuate along f (FluctDirection) or with a noise covariance Σ (MoveNoiseCov); see "Fluctuating optima" below.
  3. The kernel's images are one table with a branch, not two tables. In the kernel the object image is a World, and a World with traits set is the ℝⁿ image; the operators develop!, select! and mutate! branch on it (and call develop_traits! etc.). So lower(f, :kernel) is one table whose images dispatch on the object image, rather than a second table. That is a Julia convenience: semantically they are two functors, and the trait moments lowering is written as a genuinely second table (trait_moment_images, passed as images) to show that the syntax is shared. Now addressed: kernel_images(model) is two tables, chosen by lower(f, :kernel; model).
  4. QTSim's scalar outputs are a projection. record's QTSim columns (pheno_mean, geno_var, theta) describe trait 1; the trait columns are additional. The SLiM model's output format, the golden file and the parsers are keyed to the scalar columns.

Models: step parameters and images belong to the model

The three findings above have one cause: the model (one trait or n) was implicit, read off the World at run time, while step parameters were checked against one global table. src/models.jl makes it explicit and keeps it minimal and concrete:

  • QTLSim.Model, with two instances, OneTraitModel() (QTSim's) and TraitModel(n); model_of(p) is the model of a Params.
  • Each model declares its own parameter schema per step (step_schema(model), from step_fields, the fields of Params a step's image reads, and step_own_params, the parameters that are not fields, each with a checker). For one trait, select takes a number θ and ω (and StandardisePhenotype); for n traits, select takes a vector θ of n, a fitness covariance matrix Ω (in place of ω² S), ω, SelCorr and MoveDirection, and mutate also takes MutCorr and MutCov. STEP_PARAMS survives as step_schema(OneTraitModel()).
  • withparams validates against a model: withparams(f; kw...) against QTSim's, withparams(f, model; kw...) or withparams(f, p; kw...) against model or model_of(p). lower validates again against the model it targets (lower(f, target; model)), so withparams(g; θ = 0.1) lowered for two traits, or withparams(g, p2; θ = [0.1, 0.0]) lowered for one, is an ArgumentError at lowering, not a wrong run. The parametrised generators Step(name, params) are unchanged: the presentation stays model-independent, and the parameters are typed where they are interpreted.
  • Each model has its own table of images in each backend: kernel_images(model, rec), moment_images(model, rec) and eidos_images(model), chosen by lower(f, target; model). The two kernel tables share the images of reproduce, record, rescale and swap (shared_kernel_images) and differ in develop, select and mutate, which call develop_one!/develop_traits! etc. directly; each image refuses a population of the other model. develop!, select! and mutate! remain as the monolithic run!'s dispatchers. So lower(f, :kernel; model = TraitModel(2)) is visibly a second functor from the same syntax. run_composed, run_moments and slim_script pass model_of(p); a metapopulation must be of one model.
  • How a step's parameters act is per model (with_step_params(model, s, op) for the kernel and the moments, eidos_with_params(model, s, code) for Eidos). For n traits a step's θ replaces the optimum vector, Ω the width (1) and the fitness shape, and the Params fields that define the state's derived matrices replace them for the step: the inverse shape S⁻¹ (SelCorr), one mutation's covariance (MutationScalar, MutationRatePerGamete, MutCorr, MutCov) and the move direction. In Eidos they are literals (THETA = c(…), SINV, UDIR, MUTCOV), so per-deme trait parameters in a SLiM model go through steps: withparams(g, p; θ = [0.1, 0.0]) ⊗ withparams(g, p; Ω = …) ⋅ L.migrate(2) gives each deme its own optimum vector or fitness covariance, while slim_script(f, [p1, p2]) still requires the demes' trait fields of Params to agree.

What this shows about generalisation:

  • The syntax needed no change; the change was to make the codomain side of each functor a first-class value. A model is exactly the data of a family of functors from the same free category: an object image, a table of step images per backend, and the parameter space of each parametrised generator. That is the shape a general framework would have (a model as an instance), and it is what a third model would implement.
  • Parameters are not uniform across models even for the same step: select's θ lives in the object image (ℝ or ℝⁿ), Ω exists only where the object image has more than one dimension, and StandardisePhenotype has no n-trait meaning. A step's parameter space is a function of the model, which is why one global table could not work.
  • Typing at lowering, not at construction, keeps the presentation free: the same withparams(L.select; ω = 0.3) is valid in both models, since ω is in both schemas.
  • It found a silent bug: before, a step's MutationScalar (or MutationRatePerGamete) on a population of traits was ignored in the kernel and in the moments, because the trait state's mutation matrix was derived from the deme's Params once, not from the step's. With the derived matrices part of what a step's parameters replace, a step's mutation fields now give the run of Params with those values, bit for bit (tested).
  • One trait is bitwise unchanged: 36 hashes before and after (simulate in three regimes, run_composed with and without step parameters, two demes with and without, Beverton–Holt, fecundity, red noise, periodic, run_moments in six configurations including two demes with between = true, trait runs, and 13 slim_script outputs), the golden file and check_generated.jl. A generation still allocates nothing, now also with a step that overrides fields of Params (an IdDict keyed by the immutable Params boxed the key, 272 bytes per generation; a typed vector searched by === does not).

What remains: record is shared (its trait columns are added when the World carries traits) rather than per model; slim_script's per-deme Params cannot vary the trait fields (use steps); checkparams still knows both models (checktraits); and a model is chosen from NoTraits, not declared, so Params remains the union of both models' parameters. A general framework would let a model own its Params.

What is implemented

  • Params (src/params.jl): NoTraits, MutCorr, SelCorr, MutCov, SelCov, MoveDirection, checked by checkparams; mutational_covariance, selection_shape, selection_covariance, move_direction. Params now compares by value (it holds arrays).
  • Kernel (src/blocks.jl, src/model.jl, src/traits.jl): one block pool per population as before, a block holding n values per locus (locus by locus) and caching n sums, so that a gamete still copies contiguous runs and shares blocks; with n = 1 the layout and every operation are the old ones. World.traits (a TraitState) holds the n × N genotypes, phenotypes and environments, the optimum vector and the precomputed S⁻¹ and M^{1/2}. QTSim's one-trait path is untouched: runs are bitwise identical to before (12 runs in four regimes compared by hash), the golden SLiM file is unchanged, and a generation still allocates nothing (nor does one of n traits).
  • Records: trait_mean, gmatrix, pmatrix, trait_lag (θ − z̄), trait_sel_diff, one vector or matrix per recorded generation.
  • Theory (src/traits_theory.jl): see the next section.
  • Moments lowering (ext/QTLSimCatlabExt/trait_moments.jl): trait_moment_images, a second table for the seven steps on a TraitMoments state (mean vector, G, P, optimum vector), lowered from the unchanged lifecycle() by lower(f, :moments; images = trait_moment_images(rec)). run_moments(p) uses it when NoTraits > 1; with NoTraits = 1 the table runs 1×1 matrices and reproduces moments.jl's one-trait recursion with loci = :multilocus to 1e-10, with and without drift's erosion, with a move and a width change. Several demes too (run_trait_moments(ps; cycle), see "The moments of several demes" below).
  • Eidos lowering (ext/QTLSimCatlabExt/eidos_traits.jl): eidos_trait_images, a second table of Eidos for the seven steps. An individual's a0/a1 hold L·n values (the kernel's layout), THETA is a vector on the deme's subpopulation, genotypes and phenotypes are n × N matrices, fitness uses matrixMult with the constant SINV, mutation draws with rmvnorm from MUTCOV = M/(2L·rate), and record appends the trait means, G's upper triangle and the optimum to QTSim's columns. slim_script picks the table when NoTraits > 1; the one-trait model is byte-identical (golden file) and check_generated.jl still passes. Migration's image is unchanged (it swaps whole allele vectors), and the fecundity splice applies to the trait table unchanged, because the spliced segments are verbatim the one-trait ones. Limits: the demes of a SLiM model share the trait parameters, M must be positive definite (rmvnorm), and a step's own θ is rejected (as in the kernel and moments lowerings, where it would otherwise be a scalar for a vector); a step's own vector θ, Ω, SelCorr, MoveDirection and mutation fields lower to literals.

The theory

With P = G + V_E I, A = Ω + V_E I (the matrix V_s) and λ = θ − z̄, Gaussian selection on a Gaussian population gives (Lande 1979)

Δz̄ = G (A + G)⁻¹ λ = G β,        G_survivors = G − G (A + G)⁻¹ G,

and with mutation G' = G − G (A + G)⁻¹ G + M. One trait is the scalar recursion of theory.jl (A + G = V_s + V_G). This is the aggregate (one haploid locus) recursion, run_moments(p; loci = :aggregate); the default multilocus model applies the same selection to the haplotype moments of src/multilocus.jl, as matrices.

  • Equilibrium G (gaussian_G, of the aggregate recursion; gaussian_G_loci for L recombining diploid loci is gaussian_G(2L·M, A)): the unique positive semidefinite solution of G (A + G)⁻¹ G = M is G = A^{1/2} X A^{1/2} with X = ½ (M̃ + (M̃² + 4M̃)^{1/2}), M̃ = A^{-1/2} M A^{-1/2}, for any M and A, not only when they share eigenvectors. When they do, G has their eigenvectors and the one-trait formula on each axis. For weak mutation G ≈ A # M, the matrix geometric mean (Lande 1980). gaussian_G_iterate iterates the recursion as a numerical check, optionally with drift's erosion.
  • Steady lag (steady_lag_vector): an optimum moving by k = d·u per generation is tracked with G (A + G)⁻¹ λ = k, so λ = (A + G) G⁻¹ k; for one trait k (V_G + V_s)/V_G. The mean moves exactly along k in the steady state, but the lag is deflected away from g_max: it is longest where genetic variance is least.
  • Line of least resistance (response_deflection, gmax): the response G β turns from the gradient β toward g_max (Schluter 1996): in G's eigenbasis each component of β is scaled by its eigenvalue, so the angle to the g_max axis can only shrink.

Fluctuating optima

MoveType = :red_noise and :periodic with several traits (checkparams no longer rejects them): with t the generations since the move's start, θ_t = θ0 + d t u + ε_t, ε a vector AR(1) process with stationary covariance Σ (MoveNoiseCov, by default MoveNoiseSD²·f fᵀ, noise along one direction) and autocorrelation ρ, or θ_t = θ0 + d t u + A sin(2π t/P)·f, with f the unit vector of FluctDirection (u by default; fluct_direction, move_noise_covariance). The kernel (moveoptimum_fluct!) draws n normals per generation for red noise and allocates nothing; the moments lower a fluctuating move to its expectation (the cycle exactly, red noise as its trend) and take a realised optimum sequence (optimum, a vector per generation); the Eidos images splice the move into the trait table's select only when a deme or a step uses it (FDIR, NOISEROOT = Σ^½, EPS as deme state), so other trait models are byte-identical. A step's own MoveNoiseCov, MoveNoiseSD and FluctDirection act as the other step parameters do. In a SLiM model the demes share FluctDirection, MoveNoiseCov and MoveNoiseSD (vary them through steps). One gap: a step that sets MoveDirection but not FluctDirection cycles along the step's u in the kernel and the moments, and along the deme's f in Eidos.

Theory (src/traits_theory.jl): with the mean following z̄' = z̄ + B (θ − z̄), B = G (A + G)⁻¹, the lag and the AR(1) noise form the linear system λ' = (I − B) λ + (ρ − 1) θ + √(1 − ρ²) η, θ' = ρ θ + √(1 − ρ²) η, whose stationary covariance solves a discrete Lyapunov equation; red_noise_lag_cov(Σ, ρ; G, A) is the lag block, exactly red_noise_lag_var for one trait. A cycle gives the lag Re(l e^{iνt}) with l = (I − e^{−iν}(I − B))⁻¹ (1 − e^{−iν}) f, so periodic_lag_cov(P, f; G, A) = Re(l l*)/2, exactly periodic_response's lag_amplitude²/2 for one trait. expected_lag_cov(p; G) adds the trend's steady lag outer product, and trait_lag_load(p; G) = tr((Ω + P)⁻¹ E[λλᵀ])/2. Both formulas are tested against the iterated (periodic, to 1e-3) and simulated (red noise, 400,000 steps, to 3%) recursion.

Validation, validate/slim/compare_traits_fluctuating.jl (log valid_traits_fluctuating.log, criteria fixed before the run, 40 runs per backend): two traits, red noise with Σ = [0.2 0.05; 0.05 0.1], ρ = 0.7, and a cycle of amplitude 0.6 and period 25 along (1, −1)/√2. Kernel against SLiM, KS tests on the lag's covariance and G: smallest p = 0.263. Kernel against theory with the kernel's G, each entry within 10% of sqrt(Λ_ii Λ_jj): largest deviation +8.5% (red noise, L22) and +7.8% (cycle, L11), all passing. The diagonals are systematically 4–8% above the theory while the off-diagonals are within 2%: an isotropic excess of about 0.005, consistent with what the deterministic theory leaves out (drift of the mean, restrained by selection, and the sampling error of the recorded mean phenotype, P/N).

The moments of several demes

run_trait_moments(ps; cycle, migration_rate, between, erosion, loci) (and run_moments for NoTraits > 1 on a life cycle of k demes) is moments.jl's k-deme lowering with every moment a matrix: TraitCov holds each deme's haplotype moments T, R, Q_aa by pair class, and the cross-moments Q_ab = E[(h − z̄_a/2)(h′ − z̄_b/2)ᵀ]. Selection in deme a shrinks its mean's deviation by I − B_a, B_a = G_a s_a⁻¹, so Q_ab ← (I − B_a) Q_ab; migration mixes means, haplotype moments and cross-moments with the outer products Δ_ac Δ_bdᵀ of the differences of the means in place of their squares (the cross-moment mixing is one (n², k²) × (k², k²) product per pair class). With between = true it returns metapop: the mean within-deme G, the covariance matrix of the deme means, its part beyond sampling, and Q_ST per trait. With one trait it reproduces moments.jl's k-deme moments to 1e-15 (between = true, erosion, loci = :aggregate; tested). The code is in trait_moments.jl; moments.jl gains one line, the dispatch.

Validation, validate/trait_moments_demes.jl (log trait_moments_demes.log, criteria fixed before the run, 200 kernel runs per scenario, passed on the first run): four demes of 100 diploids, 50 loci, two traits (MutCorr 0.3, SelCorr 0.2), island migration at forward rate 0.01. Neutral (T0): every |z| ≤ 2.13 for G, the among-deme covariance and both QST. Local optima at distance 2 along 0°, 60°, 120° and 180° (T1): within-deme G within 6.8% of scale, among-deme covariance within 8.6%, QST 0.349/0.164 against 0.323/0.151 (+8%), every deme mean within 1.5% of |θ|, and the deflection of the deme means from their optima (21°, 67°, 113°, 160° for optima at 0°, 60°, 120°, 180°, by migration and through G) within 0.5° of the moments'. As for one trait (moments_demes.log), the moments underestimate the differentiation by a few percent under local adaptation.

For Lean

New identities the Julia code relies on, for the Lean layer:

  1. Multivariate mutation input: if each of K ~ Poisson(λ) mutations adds an independent N(0, C) vector, the expected covariance added is λ C; with λ = Ploidy·L·rate and C = M/(Ploidy·L·rate) it is M (the matrix version of mutationalVarianceInput_eq; equivalently the scalar lemma for every vᵀ M v).
  2. Gaussian selection on a Gaussian vector: for z ~ N(z̄, P) and W ∝ exp(−½ (z−θ)ᵀ Ω⁻¹ (z−θ)), the selected distribution is N(z̄ + P (Ω + P)⁻¹ λ, P − P (Ω + P)⁻¹ P), and the regression of g on z gives the genotype's moments above (matrix algebra: (P⁻¹ + Ω⁻¹)⁻¹ = P − P (P + Ω)⁻¹ P).
  3. Equilibrium: X (I + X)⁻¹ X = M̃ with X ⪰ 0 has the unique solution X = ½ (M̃ + (M̃² + 4M̃)^{1/2}), hence gaussian_G; with n = 1 it is gaussian_fixed_point.
  4. Steady lag: G (A + G)⁻¹ λ = k iff λ = (A + G) G⁻¹ k (G, A + G invertible); with n = 1, steady_lag_response.
  5. Deflection: for G symmetric positive definite with eigenvalues g_1 ≥ … ≥ g_n and leading eigenvector e_1, |cos∠(Gβ, e_1)| ≥ |cos∠(β, e_1)|.
  6. Lag under AR(1) forcing: the stationary covariance of the linear system x' = F x + w (F stable, w of covariance Q) is the unique solution of X = F X Fᵀ + Q; with n = 1 and the system of red_noise_lag_cov, its lag entry is 2σ²(1 − ρ)/((2 − β)(1 − ρ(1 − β))) (red_noise_lag_var). A finite-dimensional, purely algebraic statement (the Lyapunov equation's solution as the series Σ Fᵏ Q Fᵀᵏ).
  7. Periodic lag: l = (I − e^{−iν}(I − B))⁻¹ (1 − e^{−iν}) f solves the steady recursion of a sinusoidal optimum, and for n = 1 |l|² = (2 sin(ν/2)/D)².
  8. Model-typed step parameters: a functor out of the free category on the stages and steps, extended by parametrised generators Step(name, params), is fixed by its images on all generators, so two models (two tables) that agree on the plain steps differ only through their parameter spaces; Lowering.lean's lower_unique covers this once the parametrised generators are generators of the quiver.
